# CasesBot

Бот-сборщик кейс-презентаций для отдела продаж (VK Teams + PHP-монолит).
Полное описание задачи, требований и архитектуры — в [`ТЗ_бот-сборщик кейс-презентаций v1.1.md`](./ТЗ_бот-сборщик%20кейс-презентаций%20v1.1.md).

## Структура проекта

```
CasesBot/
├── bin/                # CLI-скрипты: index.php, poll.php (VK Teams), presentations-list.php, build-test.php, deck-test.php, build-public.php, sync.php (Google Drive)
├── config/             # Config, справочник тегов (TagTaxonomy), .env; config/google/ — ключ сервисного аккаунта Google (не в git)
├── presentations/       # Исходные .pptx — НЕ в git (см. .gitignore), заливаются на сервер отдельно при деплое
├── presentations-public/ # «Парадные» копии (PublicCopyBuilder) — без заметок/комментариев, их отдаёт :8080; генерируются, не в git
├── public/              # index.php — точка входа для вебхука VK Teams (не используется, бот работает через long polling, см. bin/poll.php); upload.php — веб-загрузчик презентаций (:8081)
├── python/              # SlideTextExtractor / SlideCloner (python-pptx, lxml) — вызываются из PHP как подпроцесс
├── src/
│   ├── Api/Providers/   # LLM-провайдеры (Ollama, OpenCodeZen) для дополнения тегов кейсов
│   ├── Bot/             # ChatBotController (диспетчер), Commands/ (по классу на команду), VkTeamsClient
│   ├── Catalog/         # CaseItem, CatalogRepository, TagTaxonomy, Indexer, LlmTagSuggester
│   ├── Query/           # QueryParser, Matcher
│   ├── Presentation/    # SlideTextExtractor, SlideCloner, PresentationBuilder (PHP-обёртки), CaseDeckBuilder, PublicCopyBuilder
│   ├── Storage/         # LocalPresentationsClient, GoogleDriveClient (сервисный аккаунт, JWT → OAuth2)
│   └── Config.php
├── storage/
│   ├── catalog/         # Каталог кейсов: catalog.sqlite + schema.sql + images/ (картинки со слайдов)
│   ├── incoming/        # Резерв на будущее (если источник вернётся на скачивание, напр. Google Drive)
│   ├── output/          # Собранные pptx перед отправкой в чат
│   └── logs/            # Журнал запросов (P1)
├── tests/
│   ├── Unit/
│   └── Fixtures/        # Тестовые pptx для проверки сохранения форматирования
└── docs/                # Дополнительная документация по мере появления
```

## Индексация каталога

`php bin/index.php` обходит `presentations/`, извлекает текст и картинки слайдов
(`python/slide_text_extractor.py`), но только для слайдов, помеченных экспертом меткой `#кейс#`
в заметках докладчика (не видна ни на слайде, ни в показе) — остальное (обложка, о компании,
контакты) пропускается автоматически.

Предложенные теги для помеченных слайдов собираются из трёх источников: (1) теги, которые эксперт
сам перечислил в тех же заметках после метки (`#кейс#\n1с, ритейл`) — им доверяем больше всего;
(2) LLM по содержимому слайда (`LlmTagSuggester` через `src/Api/Providers`, провайдер и модель —
в `.env`: `AI_PROVIDER`, `OLLAMA_*`/`OPENCODEZEN_*`); (3) простое совпадение по словарю
`config/tags.php`. Теги плоские, без категорий (§6.2 ТЗ изначально предполагал
industry/product/technology/client — от категорий отказались в пользу простых тегов).

`Indexer::run()` (CLI, `bin/index.php`) даёт эксперту поправить итог интерактивно за один проход
(Enter — принять предложенное, `skip` — пропустить, свои теги — через запятую), плюс необязательную
ссылку на сайт (`site_url`). `Indexer::runAutomatic()` (веб-загрузчик, см. ниже) сохраняет
предложенное сразу, без диалога — ручная курация тегов в этом случае уже сделана экспертом в
заметках докладчика при подготовке слайда (ТЗ v1.2, §5.1.8); словарь/LLM лишь дополняют, не решают
за эксперта.

Полный текст сохраняется в `cases.content`, картинки — файлами в `storage/catalog/images/` со
ссылками в `case_images`. Повторный запуск обновляет те же записи, не создавая дублей.
Автоматическая переиндексация (веб-загрузчик, sync) атомарна: очистка и заполнение идут в
одной транзакции SQLite (WAL-режим), при сбое каталог откатывается к прежнему состоянию и
бот не видит пустую базу; параллельный запуск исключается flock-локом (Reindexer).

## Синхронизация с Google Drive (раз в неделю)

`bin/sync.php` + недельный цикл в `docker/entrypoint.sh` (`SYNC_INTERVAL_SECONDS`, по умолчанию
604800 = 7 дней; первый прогон — сразу при старте контейнера). Источник — презентации из
`GOOGLE_PRESENTATION_ID` (можно несколько, через запятую), доступ — сервисный аккаунт Google
(`GOOGLE_SERVICE_ACCOUNT_JSON`, ключ в `config/google/`, папка/файл расшарены на его email).

Алгоритм идемпотентен: сверяет `modifiedTime`/`md5` файла в Drive с состоянием последней
синхронизации (`storage/catalog/drive-sync.json` — папка примонтирована, переживает рестарт
контейнера). Ничего не изменилось — ничего не делает; изменилось — скачивает pptx (нативный
Google Slides — через экспорт `.../export/pptx`, загруженный .pptx — как есть) в
`presentations/` под именем из Drive, запускает переиндексацию каталога (тот же
`Indexer::runAutomatic`, что в веб-загрузчике, через общий `Reindexer`) и пересобирает
публичные копии. Эксперт меняет презентацию в Google Slides — раз в неделю она сама приезжает
на сервер, каталог и «парадные» копии обновляются без его участия. Ручной запуск:
`php bin/sync.php`, флаги `--skip-reindex` и `--force`.

## Веб-загрузчик презентаций

`public/upload.php` (отдельный `php -S` на `:8081`, см. `docker/entrypoint.sh`) — простая страница
для эксперта без консоли: загрузить `.pptx` (то же имя файла = новая версия существующей
презентации, перезаписывает старую) и кнопкой запустить переиндексацию. Переиндексация заодно
пересобирает публичные копии (PublicCopyBuilder — см. «Сборка презентации»); удаление
презентации снимает и её публичную копию. Защищена HTTP Basic Auth
(`UPLOAD_USERNAME`/`UPLOAD_PASSWORD` в `.env`) — без обоих значений страница отказывает в доступе,
а не открывается всем без пароля.

Переиндексация здесь идёт через `Indexer::runAutomatic()` — в отличие от интерактивного
`bin/index.php` (Enter/skip/свои теги по каждому слайду в терминале), автоматический режим
сохраняет предложенные теги сразу, без диалога подтверждения: тегирование уже вручную сделал
эксперт в заметках докладчика при подготовке слайда (ТЗ v1.2, §5.1.8) — веб-страница лишь
запускает индексацию по всем презентациям и показывает отчёт.

## Сборка презентации

`SlideCloner` (`python/slide_cloner.py`) копирует слайды между презентациями на уровне сырых частей
OOXML-пакета (python-pptx opc/package API, не через объектную модель) — слайд, его layout, master,
theme и все media копируются как есть, с ремаппингом id/media/layout-master. Внутренние пометки
не копируются вообще: заметки докладчика (там `#кейс#`/теги эксперта) и комментарии рецензентов
(в т.ч. перенесённые в pptx экспортом Google Slides, старый и современный формат) отсекаются
на уровне связей пакета / отдельных элементов XML — структура и форматирование слайдов от этого
не меняются. Проверено: форматирование (кастомные шрифты, цвета, размеры) сохраняется
побайтово идентично оригиналу.

Важно: сборка подборок идёт через **prune** (SlideCloner::prune — байт-в-байт копия исходника
минус лишние слайды и без заметок/комментариев), а не пересборку пакета через новую
Presentation() (clone). Причина: пакет google-экспорта, пересобранный python-pptx'ом с нуля,
PowerPoint не открывает вовсе (0x80070570, «файл повреждён», исследовано PowerPoint COM
04.11.2026), а исходный пакет открывается; prune и раньше частично давал «repair»-режим.
Экспорт Google Slides → pptx может содержать части пакета с разными блобами под одним
именем — это тоже исправлено (имена частей раздаются с реестром занятых на всю сборку).

`PresentationBuilder` вызывает `SlideCloner` для нужных слайдов, затем сам добавляет титульный слайд
(тема + дата) и сохраняет финальный файл в `storage/output/`.

`CaseDeckBuilder` — другой сценарий сборки, для команды `кейсы`: из исходной презентации убирает
все слайды с меткой `#кейс#` в заметках докладчика, кроме тех номеров, что нашлись по запросу
(`SlideTextExtractor` определяет метку, `SlideCloner` копирует нужные слайды в исходном порядке).
Титульный слайд не добавляется — получившийся файл читается как урезанная версия оригинала.
PDF как формат вывода не используется — LibreOffice headless на Alpine/musl (текущий базовый образ)
падает на старте (баг совместимости, проверено на сервере), поэтому отправляется pptx.

### Публичные копии без пометок (PublicCopyBuilder)

Бот, кроме вложения-подборки, присылает ссылку на оригинал презентации целиком. Оригинал
содержит заметки и комментарии — их не должен видеть клиент, поэтому по HTTP на :8080
(docker/entrypoint.sh) отдаётся каталог `presentations-public/`: «парадные» копии без
заметок/комментариев — пакет исходника минус ничего (все слайды на месте), где заметки и
комментарии вычищены (`SlideCloner::cloneAll()` → prune, см. ниже). Пересобираются после
переиндексации (`public/upload.php`), из sync-шага Google Drive и вручную
(`bin/build-public.php`).

Имя копии можно переопределить независимо от имени исходника:
`config['presentations']['public_name_overrides']` (исходник на Drive -> имя в чате), например
копия «Кейсы направления Бизнес автоматизации.pptx» отдаётся как «Экспертиза направления
Бизнес автоматизации.pptx». При каждой пересборке из папки удаляется всё, что не является
актуальной копией (старые версии, прежние имена, копии удалённых исходников) — в
`presentations-public/` остаётся ровно актуальный набор. Сырые исходники остаются только
для индексации.

Проверка `CaseDeckBuilder` без чат-интеграции:
```
php bin/deck-test.php "Экспертиза направления бизнес автоматизации.pptx" "7,9"
```

## Команды бота

Команды — отдельные классы в `src/Bot/Commands/`, реализующие `CommandInterface` (`matches()` +
`handle()`); `ChatBotController` перебирает их и передаёт управление первой подошедшей. Добавить
новую команду — значит просто добавить новый файл в эту папку и зарегистрировать его в `bin/poll.php`.

**`кейсы`** (`CasesCommand`) — ищет и ранжирует кейсы по тегам (`CatalogRepository::findByTags`,
больше совпадений — выше, лимит `MAX_SLIDES_PER_DECK`, §5.1.3 ТЗ). Теги — простые слова через
запятую/пробел (без категорий), с резервом на синонимы (`TagTaxonomy`, `config/tags.php`) —
свободный текст всей фразы целиком (`QueryParser`) ещё не реализован:
```
кейсы ритейл
кейсы производство, 1с
```
По каждой затронутой исходной презентации собирает и отправляет pptx-подборку (`CaseDeckBuilder`,
см. «Сборка презентации» выше), а следом — в любом случае — ссылку на оригинал презентации
целиком и номера слайдов, которые нужно оставить, если подборку нужно поправить вручную. Если
сборка не удалась (или `CaseDeckBuilder` не настроен) — присылается только ссылка.

Если ничего не найдено — бот присылает список реально используемых в каталоге тегов вместо пустого
файла (§5.1.7 ТЗ).

Если же ни одно слово запроса вообще не совпало ни с одним известным тегом (ни в `TagTaxonomy`, ни
в базе), а LLM-провайдер настроен (`.env`: `AI_PROVIDER`, `OLLAMA_*`/`OPENCODEZEN_*`), команда не
сдаётся сразу с подсказкой по тегам, а отдаёт запрос целиком и текст всех видимых кейсов каталога
(`CatalogRepository::allForMatching` — текст уже лежит в `cases.content` с момента индексации,
повторно читать презентации не нужно) в `LlmCaseMatcher`. Модель либо возвращает id кейсов,
подходящих по смыслу (отрасль/продукт/технология/клиент), либо явно отвечает, что подходящих нет —
тогда бот показывает тот же список доступных тегов, что и при обычном пустом результате. Без
настроенного провайдера поведение прежнее — подсказка с примерами синтаксиса.

Проверка без чат-интеграции — то же самое, что делает команда, но из консоли:
```
php bin/build-test.php "производство, 1с"
```

## Этапы разработки (§9 ТЗ)

1. **Недели 1–2** — `Indexer`, `CatalogRepository`, `TagTaxonomy`: построение каталога, проверка тегирования/поиска через `bin/index.php`. ✅
2. **Недели 3–4** — `SlideCloner`, `PresentationBuilder`: сборка pptx (готово, проверено на форматировании) ✅; команда `кейсы` в VK Teams ✅ — но по явным тегам, не свободному тексту (`QueryParser` с синонимами ещё нет).
3. **Неделя 5+** — пилот на реальных запросах, донастройка справочника тегов и лимитов.
